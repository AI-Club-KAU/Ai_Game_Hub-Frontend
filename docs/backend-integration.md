# حالة ربط Backend

Backend مدى جاهز بحسب إفادة صاحب المشروع؛ تفاصيل الاستدعاء لم تصل بعد. التطبيق يعمل باستخدام Mock فقط.

## نقاط الاستبدال الموجودة

| الوظيفة | واجهة الخدمة |
| --- | --- |
| التحقق من الوصول | src/services/access-service.ts |
| تسجيل/استرجاع المشارك | src/services/participant-service.ts |
| الأهلية والجدول | src/services/eligibility-service.ts |
| بدء/استعادة المحاولة | src/services/attempt-service.ts |
| حفظ/استعلام النتيجة | src/services/result-service.ts |
| أفضل ثلاثة | src/services/leaderboard-service.ts |

تستورد الشاشات الخدمات من src/services/index.ts. تُضاف المحولات الحقيقية بعد قراءة توثيق مدى، وتُحوّل الاستجابات إلى احتياجات الواجهة الحالية دون فرض هذه الأنواع على Backend.

## عند وصول التفاصيل

1. مطابقة التوثيق مع احتياجات docs/backend-requirements.md، وتحديد الجلسة وصلاحيتها.
2. استبدال الخدمات وإزالة أدوات Mock وحقول التحكم التجريبية، دون الرجوع إلى Mock تلقائيًا عند فشل الخدمة الحقيقية.
3. الاتفاق مع الأقسام على انتهاء اللعبة ومصدر النتيجة الموثوق؛ زر النتيجة 80 مؤقت.
4. اختبار التسجيل المكرر، بدء متزامن من بوثين، فقد رد الحفظ واستعادته، إعادة تحميل الصفحة، انتهاء الجلسة، وتحديث المتصدرين باستخدام بيئة الاختبار.
5. التحقق من حفظ النتيجة مرة واحدة وبدء 10 ثوانٍ بعد التأكيد فقط، ثم تنظيف شاشة المشارك.

هذه خطوات ربط معلقة؛ لم تُنفذ اختبارات Backend أو ألعاب الأقسام بعد.
